# בדיקות יחידה לחומרה (HW Unit Tests)

קבוצה A2, קורס IoT, קיץ 2026. כל בדיקה היא sketch עצמאי שבודק רכיב אחד בלי שום רשת או ענן, כדי שתקלה בחומרה תתגלה לבד ובשיטת אלימינציה. כל sketch מחזיק עותק של הפינים שלו (אותם פינים כמו ב-`ESP32/parameters.h`), ולכן אפשר לפתוח אותו ישירות ב-Arduino IDE ולצרוב.

**איך מריצים:** פותחים את התיקייה של הבדיקה ב-Arduino IDE (‏ESP32 Dev Module), צורבים, ופותחים Serial Monitor ב-115200. בדיקה אוטומטית מדפיסה `===== ... PASSED =====` או `FAILED` עם הסיבה. בדיקה שצריך לראות או לשמוע אומרת בדיוק למה לשים לב.

כולן מתקמפלות עם ESP32 core 2.0.17 (נבדק עם `arduino-cli compile`).

## בדיקה 08 והחשד לגבי MCLK

בשלבים 19-20 כפתור BOOT נתן קריאות שווא, והחקירה לא הסתיימה. בשלב ההגשה מצאנו סיבה אפשרית: השדה `mck_io_num` בהגדרת ה-I2S לא היה מאותחל (כלומר 0), ומנהל ההתקן של ה-ESP32 מוציא אז את שעון ה-MCLK ל-GPIO0, הפין של הכפתור.

**איך בודקים:**
1. מריצים את בדיקה 08 כמו שהיא (`kStartI2sWithMclkOnGpio0 = false`). כשלא נוגעים בכפתור לא צריכים להופיע שינויים גולמיים.
2. משנים ל-`true`, וזה מפעיל I2S כמו בקושחה הישנה. אם החשד נכון, יופיעו מאות או אלפי שינויים בשנייה בלי לגעת בכפתור.

הקושחה מוגדרת עכשיו בלי פין MCLK (`I2S_PIN_NO_CHANGE`). כפתור BOOT בקושחה נשאר כבוי עד שמדליקים אותו ממרכז הבקרה (On the board itself), אחרי שהבדיקה עברה.

## בדיקות 02-04 וה-MCLK

בדיקות 02-04 נשארו כמו שנכתבו בשלבים 2-4, ולכן גם בהן `mck_io_num` לא מאותחל (3 אזהרות קומפילציה). זה לא משפיע על מה שהן בודקות: הרמקול והמיקרופון לא משתמשים ב-MCLK.

## בדיקות של שירותי הענן

את החיבור ל-OpenAI בדקנו בשלבים 9-11 (חיבור מוצפן, הגדרת סשן, שאלה ותשובה בטקסט). הם נמצאים ב-`Documentation/development_steps/`, כי הם תלויים במודולים המשותפים כפי שהיו אז. הכלי `tools/realtime_audio_diagnostic.py` מריץ את אותו רצף הודעות מהמחשב, בלי ה-ESP32, כדי להבדיל בין תקלה בצד השרת לבין תקלה בלוח (נבנה לאבחון הניתוק של שלב 13).
