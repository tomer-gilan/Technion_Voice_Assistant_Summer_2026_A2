# מקרי קצה - עוזר קולי על ESP32

קבוצה A2, קורס IoT, קיץ 2026.

לכל מקרה: מה המשתמש רואה או שומע (חיווי), ואיך המערכת ממשיכה לעבוד (התאוששות). העמודה האחרונה אומרת איך מדגימים. המספרים כאן הם אלה ש[תוכנית ההדגמה](demo-plan.md) ו-Demo checklist במרכז הבקרה מפנים אליהם.

## רשת וחיבור

| # | המקרה | חיווי למשתמש | התאוששות | איך מדגימים | ✓ |
|---|---|---|---|---|---|
| 1 | ה-Wi-Fi נופל באמצע עבודה | נורית Wi-Fi אדומה, העיגול **Offline** (`no Wi-Fi`). עם צלילי מצב: שני צלילים יורדים | ה-ESP32 מתחבר מחדש לבד; אם הרשת עדיין למטה אחרי 20 שניות, מתחיל מחדש. הטיימר והפקדים ממשיכים | מכבים את ה-hotspot ל-30 שניות ומדליקים. נורית ירוקה, Ready, ושני צלילים עולים | |
| 2 | אין Wi-Fi כשמדליקים את הלוח | נורית Wi-Fi אדומה עם הסיבה (`network not found` / `check the password`), Offline | ההדלקה ממשיכה אחרי 20 שניות. החיבור ל-OpenAI נפתח לבד כשהרשת עולה | hotspot כבוי, Reset ללוח, ואחרי ההדלקה מדליקים את ה-hotspot | |
| 3 | הרשת השתנתה (hotspot אחר, סיסמה אחרת) | כרטיס **Wi-Fi network** מראה באיזו רשת הלוח משתמש | מזינים שם וסיסמה ולוחצים Save & connect. נשמר ב-flash, בלי קימפול. **Back to default** מחזיר לרשת מ-`SECRETS.h` | מזינים hotspot של טלפון אחר | |
| 4 | יש Wi-Fi אבל OpenAI לא זמין (אין אינטרנט, מפתח לא תקף) | נורית OpenAI אדומה `offline - retrying every 30 s`, העיגול Offline (`OpenAI unreachable`) | אחרי 5 ניסיונות (המתנה שגדלה) ממשיך לנסות כל 30 שניות, לעולם לא נעצר. Talk עונה `offline` | hotspot בלי חבילת גלישה, או חיבור לנתב בלי אינטרנט | |
| 5 | החיבור ל-OpenAI נופל באמצע שאלה | `LISTEN #N FAILED: disconnected before a reply arrived`, העיגול Reconnecting | מתחבר מחדש לבד, ומונה הניסיונות מתאפס אחרי כל חיבור מוצלח | מכבים hotspot באמצע תשובה ומדליקים מיד | |
| 6 | השרת לא עונה | `LISTEN #N FAILED: no server activity for 15000 ms` | אחרי 15 שניות בלי שום הודעה השאלה נכשלת והלוח חוזר ל-Ready (לא נתקע) | קשה לגרום לזה בכוונה. רואים את זה בלוג אם קורה | |
| 7 | הטיימר נגמר כשאין חיבור | הלוח מצפצף 3 פעמים ומהבהב | הטיימר רץ על הלוח עצמו. רק ההודעה בקול צריכה חיבור, ובלעדיו היא לא נאמרת | `Set a timer for 30 seconds` ומכבים את ה-hotspot | |

## משתמש

| # | המקרה | חיווי למשתמש | התאוששות | איך מדגימים | ✓ |
|---|---|---|---|---|---|
| 13 | רעש בחדר במצב Hands-free (דפיקה, מחיאת כפיים, צעדים) | המצב נשאר Waiting for speech. אם התחילה הקלטה ונזרקה: הערה בשיחה (`too short to be speech`) | גלאי הקול לא שולח רעש ל-OpenAI. אחרי כמה רעשים ברצף הוא עוצר להאזין לכמה שניות | דופקים על השולחן ומוחאים כפיים | |
| 14 | שקט | Hands-free: לא קורה כלום. Talk: העוזר עונה במשפט כללי | שקט לא נשלח במצב Hands-free | Hands-free ושותקים, ואז Talk ושותקים | |
| 15 | Talk כשהעוזר עוד עונה | הכפתור כתוב **Busy**. `LISTEN ignored - still waiting for or playing back a reply` | הבקשה לא נשלחת, ושום דבר לא נשבר | לוחצים Talk ורווח באמצע תשובה | |
| 16 | המשתמש מתחרט באמצע | Cancel (או BOOT שוב): `LISTEN #N CANCELLED` | ההקלטה נמחקת ב-OpenAI, או שהתשובה נעצרת, והלוח חוזר ל-Ready | לוחצים Talk ואז Cancel | |
| 17 | הפסקה קצרה באמצע משפט | | ההקלטה ממשיכה עד שקט של כשנייה (אפשר לשנות ב-Stop after silence) | אומרים משפט עם עצירה קצרה. הוא נשלח כשאלה אחת | |
| 18 | בקשה שהלוח לא יכול לבצע | העוזר אומר שהוא לא יכול | המודל מכיר רק את הכלים שהגדרנו, ושום דבר לא מופעל | `Make the light blue` (ה-LED חד-צבעי) | |
| 19 | ערך מחוץ לטווח | העוזר אומר את הערך שנקבע בפועל | עוצמה בקול מוגבלת ל-10%-100% (כדי שהעוזר יוכל לאשר בקול), טיימר ל-3600 שניות. כלי שקיבל ערך לא תקין עונה בהודעת שגיאה במקום שקט | `Set the volume to 150 percent` → 100%, `Set the volume to 0` → 10% | |
| 20 | כמה בקשות בפקודה אחת | | העוזר מבצע את כולן, ומחכה לסוף כל הכלים לפני התשובה בקול | `Set the light brightness and the volume to 100 percent` | |
| 21 | חדר רועש מדי לדיבור | | שואלים בכתב: השדה שמתחת ל-Talk (`ASK`). עד 200 תווים, ולא חותך תו באמצע | כותבים שאלה ולוחצים Ask | |
| 22 | קלט שגוי בפקודה (מרכז הבקרה או Serial) | הודעה שמסבירה מה היה צפוי, והפקד חוזר לערך האמיתי | הפקודה נדחית, ושום דבר לא משתנה | `VOLUME abc`, או סיסמת Wi-Fi של 5 תווים בכרטיס Wi-Fi network | |
